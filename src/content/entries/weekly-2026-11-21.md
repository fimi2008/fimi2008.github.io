## 明显升温的两个项目

**Univer 提供可以嵌入产品的表格和文档编辑底座。** 它包含内容模型、命令系统、公式计算、渲染和编辑接口。比如采购助手生成报价后，可以把商品、数量和公式写进真正可编辑的表格，让用户修改数量，随后重新计算总价。它解决的是 AI 生成结果与用户继续编辑之间的衔接，也让应用能读取结构化结果、保存快照和处理撤销。 [本期核对的 Univer 架构与报价示例](https://github.com/dream-num/univer/blob/ac29fd8aaa3ce43cd1f672e75a596da22c132616/README.md)

Univer 本期新增约为上期的 **4.6 倍**。这表明关注明显上升。11 月 21 日发布的 v1.6.0 还涉及权限和公式等改动，但版本发布时间与榜源采样时间不同，无法据此把本周全部增长归因于这个版本。开源核心采用 Apache-2.0，商业 Web 插件、Server SDK 和 AI 扩展另有分发与许可，选型时要逐项核对需要的能力。 [v1.6.0 发布记录](https://github.com/dream-num/univer/releases/tag/v1.6.0)

**Open Code Review 把代码审查拆成确定的处理步骤和模型判断。** 它先确定变更文件、把相关文件分组、匹配审查规则，再让 Agent 检索上下文并分析问题，最后将反馈定位到代码行。一个跨多个模块的 PR 可以被拆成有边界的审查单元，减少模型读漏文件或把评论贴错位置的机会。它缩短的是初审和重复定位的过程，真实缺陷是否漏报仍要靠历史 PR 回放验证。 [本期核对的架构说明](https://github.com/alibaba/open-code-review/blob/39515dca6161fb7fd176d87704b2b10e5f7a0c36/README.md)

它从上期新增 1,648 到本期 3,764，绝对增量多了 2,116。这里既有明显的比例提升，也有新增规模的扩大。本周提交还改进了 Rust 规则和分析报告中的 token 用量展示。对团队而言，可以先测同一批已知缺陷的 PR，看有效评论、漏报和审查成本，再判断是否接入日常流程。 [本周提交记录](https://github.com/alibaba/open-code-review/commit/39515dca6161fb7fd176d87704b2b10e5f7a0c36)

## 仍在吸引大量关注的项目

**T3 Code 管理跨设备的编程会话，Orca 组织并行任务和改动评审。** T3 Code 把本机已有 Agent 接到桌面、网页和手机，让人离开电脑后仍能回应任务。Orca 把不同任务放进独立 worktree，再将终端、浏览器和 diff 放在同一个工作台。前者减少跨设备接手的摩擦，后者帮助同时管理多份进行中的改动。两者都需要配好 Agent 和运行环境，并行任务的合并仍要处理接口和依赖冲突。 [T3 Code 仓库](https://github.com/pingdotgg/t3code) · [Orca 仓库](https://github.com/stablyai/orca)

本期 T3 Code 新增 8,817、Orca 新增 6,912。T3 Code 小幅回落，Orca 小幅增加，两者都保持较高的新增。这个连续两期的结果支持“持续热门”，后续还要看跨设备稳定性、排队消息和任务恢复等实际使用问题。

**REA 把软件行为分析与本地程序分析工具接给 Agent。** 在旧系统维护、文件格式兼容和迁移研究中，团队可以用它整理应用行为、结构和证据，减少人工在多个分析工具之间来回记录的时间。它本期新增 13,142，仍是这组选项中最大的新增量，同时比上期下降约 31%。分析结论的可追溯性仍然比演示看起来多快更能决定长期使用价值。 [REA 仓库](https://github.com/morluto/rea)

**VoiceStudio 把配音、声音处理和字幕等步骤集中到本地工作流。** 对有重复音视频产出的创作者，项目的价值是统一素材、引擎和任务结果，减少在多个服务之间导出和搬运。本周的代码涉及配音流水线、转写和启动性能优化。具体速度和声音质量仍取决于选用引擎、模型及硬件，各模型许可也需要分别核对。本期新增 5,342，比上期回落约 22%。 [本期核对的 VoiceStudio](https://github.com/debpalash/VoiceStudio/tree/15cad9debde1adedad41b01a3bc8b18e6ab2f865)

**Matt Pocock Skills 把需求追问、代码库设计和评审写成可加载的工程步骤。** 它适合把“需求还没说清就开始改代码”这类反复出现的问题前置处理。本周仓库增加了 frontmatter 的解析检查，并修正一项技能描述的 YAML 写法。它提醒我们，技能是否能被安装器稳定读取，也会影响最终使用效果。仓库本期仍新增 5,269，较上期少约 23%。 [本周仓库状态](https://github.com/mattpocock/skills/tree/abeeaf95660ba9e8b7c753eb38f441ca707a8823)

**Impeccable 提供可调用的设计动作和界面检查。** 遇到已有页面字级混乱、间距不一致、交互状态不完整时，可以围绕一个设计动作做局部调整，再检查结果。相比只说“更好看”，明确的动作更容易限定改动范围。它本期新增 4,349，回落约 8%，仍保持较高关注。对已有品牌规范的团队，使用时应把组件和 token 作为共同约束。 [本期核对的设计流程](https://github.com/pbakaus/impeccable/tree/b49177d32788f2dc585c42831d845dacf1ebed2c)

**Daily Stock Analysis 将市场数据、新闻和模型分析组合成定时简报。** 用户给定关注清单，系统取回行情与事件信息，生成报告并推送到消息渠道。它省掉的是多源信息整理和重复发送的步骤，报告质量取决于数据完整性、时间戳和模型输出。本期仍新增 1,428，但较上期的 4,500 下降约 68%，更适合描述为热度回落。 [本期核对的功能与数据源](https://github.com/ZhuLinsen/daily_stock_analysis/tree/bd7b7679948475861942a8e3840b54acd554029e)

## 社区原帖里的另外两条线索

**AudioGhost 在 Reddit 获得了具体任务带来的关注。** 11 月 18 日发布的 v1.2 帖子，在 22 日采样时约有 453 票、29 条评论。它让用户输入声音描述，将某种声音提取或移除，新版能把多个声音放进独立轨道。例如户外采访混入店铺音乐时，可以尝试把背景音乐分离出来。作者同时说明，为了适配普通 GPU，精简了官方 SAM-Audio 流水线的一部分辅助模型，质量和稳定性有所取舍。票数支持它在这个社区形成讨论，不能据此计算全网增速。 [Reddit 作者原帖](https://www.reddit.com/r/LocalLLaMA/comments/1xz6xl7/audioghost_v12_remove_any_sound_from_audio_or/) · [项目仓库](https://github.com/0x0funky/audioghost-ai)

抖音 11 月 21 日的 FredTalk 盘点涉及本地剪辑、技能扫描、个人 Agent 等工具，显示这些方向具备传播入口。X 本期检索保留了一条讨论设计工具组合的 11 月 17 日原帖，样本较薄。它们帮助发现话题，具体增速判断仍依据上面的连续两期快照。 [抖音原视频](https://www.douyin.com/video/7710439121986014514) · [X 原帖](https://x.com/choopyplug1/status/2122823987306586152)

## 本周 AI 动态

**11 月 18 日，NVIDIA SkillEvaluator 发布 v1.0.1。** 新增的 HarnessCheck 面向技能发现路径、格式和宿主兼容性，动态评估则比较同任务有无技能的结果。它把技能生态的关注进一步引向“技能是否正确加载、是否改善结果”。这版能力和使用方法在同一期 Skills 周观察中展开。 [官方发布说明](https://github.com/NVIDIA/SkillEvaluator/releases/tag/v1.0.1) · [本期 Skills 周观察](/ai/skills/2026-11-21/)
