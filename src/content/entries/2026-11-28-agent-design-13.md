一笔报销同时需要财务核对发票和行政确认出差安排。财务与行政维护各自的数据，两个核对步骤也可以独立进行。这时候才有理由考虑把任务分给两个 Agent。

## 先判断复杂度落在哪儿

| 工作方式 | 适用条件 | 带来的成本 |
| --- | --- | --- |
| 单 Agent 调工具 | 目标明确，步骤共享同一套权限和上下文 | 工具契约、状态管理 |
| 按意图路由 | 每个请求主要归一个岗位处理 | 分类误差、转接和澄清 |
| 多 Agent 协作 | 同一目标需要独立权限、并行工作或专业验收 | 派工、同步、结果冲突及失败恢复 |

如果两个查询都能由当前用户授权、结果也可以直接合并，单 Agent 调工具可能足够。独立的审批职责、必须保留隔离的数据或独立的任务完成条件，会使多 Agent 的成本更容易被收益覆盖。

## 用交接产物连接成员

<figure class="article-figure agent-diagram">
  <ol role="list" aria-label="团队负责人派工、验收和汇总">
    <li><strong>负责人定义任务</strong>拆出财务核票与行政确认两个产物</li>
    <li><strong>成员独立执行</strong>按各自权限读取材料并返回证据</li>
    <li><strong>负责人验收</strong>核对范围、处理冲突或发起返工</li>
    <li><strong>汇总并交付</strong>告知用户结果，保留未解决事项</li>
  </ol>
  <figcaption>图 13 · 成员拥有独立上下文和产物，负责人持有总任务与验收条件。</figcaption>
</figure>

负责人派工时给出子任务标识、目标、可共享的输入、完成标准和截止时间。行政成员返回「行程已确认」以及可授权引用的记录 ID。财务成员返回发票核验结果和政策出处。负责人拿这些结构化产物作验收，记录异常和未解决事项，必要时发起返工。

成员不需要读完整主会话。每次派工只传足够完成工作的范围，提交产物时保留来源。队列可按成员容量控制并发，任务领取与结果写入带稳定标识。成员超时后可以改派，但负责人需要依靠任务版本判断迟到结果是否仍可接受。

## 定义汇总的完成条件

如果财务通过、行政尚未确认，用户可以看到部分进度，总任务仍保留待办。若两位成员对出差日期有冲突，负责人应核对来源或转人工。引入多 Agent 后，验收可以用一组指标看成本是否合理，例如业务完成率、重复派工次数、端到端耗时和人工返工量。
