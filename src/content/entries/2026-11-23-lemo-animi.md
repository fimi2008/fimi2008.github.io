我已经在另一台电脑上，把 **lemo-animi** 实测跑通了。

前几天刷到 [Lemomo 发的这条帖子](https://x.com/lemomo_ai/status/2123038832815907084)，说给 Codex 装上这个 Skill，讲一句想做的故事，就能做出一支定格动画。看完就想试一下，现在确认，这条路能走通。

如果你还没接触过 Skill，可以把它理解成给 AI 配了一套做事的方法。这个叫 lemo-animi，教 AI 按照一套流程做动画：写故事、准备角色和场景，让角色动起来，配声音，最后把片子交给你看。

我想聊的，是普通人拿到它以后，能做点什么，以及第一支片子怎么开始。

## 我会先拿它做一支小故事

比如，给朋友做一段生日祝福。

平时发一句“生日快乐”，或者套个相册模板，也挺好。如果想多花点心思，可以把朋友的小习惯写进故事：一只总爱迟到的小熊，为了准时送蛋糕，提前一天就出了门，结果守在门口睡着了。最后朋友开门，它抱着蛋糕醒过来。

几十秒就够。角色可以自己设定，结尾再放一句想说的话。这样的片子有具体的人和事，做出来才有意思。

另一个用途，是把自己编的小故事做给孩子看。小兔子第一次自己睡觉，小企鹅学做早餐，小鸭子走丢以后找到回家的路，都适合这种短片。故事简单一点，角色少一点，让孩子看得懂角色想干什么、遇到了什么麻烦，最后怎么解决。

喜欢画画的人，也可以拿自己画的小角色试试。给它起个名字，安排一次小冒险，看看它从一张画变成会动的角色是什么感觉。项目支持用角色参考图来准备素材；最好在开工前先看角色和背景，确认长相对不对。

我自己还想到一个用途：给「开练」做一段轻松的开场小故事。比如一个小木偶出门前总说“明天再练”，最后终于换好鞋走了出去。这是我接下来想试的方向，先做十几二十秒，看看放进产品介绍里合不合适。

这些事的共同点是，**故事可以很小，但最好有一个你真想表达的意思。**

## 第一支片子，我建议从 20 秒开始

先说使用条件。目前项目主要面向 macOS 和 Linux，需要能使用 Codex，并且账号有可用的生图额度。Claude Code 也支持，不过还要接好生图工具。已经在用 Codex 的人，可以先从它开始。

项目地址是 [lemomo-ai/lemo-animi](https://github.com/lemomo-ai/lemo-animi)。按当前仓库说明，在终端执行下面两条命令安装，再新开一个对话：

```sh
codex plugin marketplace add lemomo-ai/lemo-animi
codex plugin add lemo-animi@lemomo-ai
```

不熟悉环境配置，可以先把仓库链接发给 Codex，让它按照项目说明检查需要准备什么。第一次要下载运行环境和配乐素材，项目估算大约 1.7 GB；缺少视频处理工具或其他依赖时，也得先处理好。

装好以后，我建议第一支先做 **20 秒、一个主角、一件小事**。先看角色能不能保持一致，动作看不看得明白，故事能不能讲完。

比如可以把下面这段直接发给它。这是一份方便上手的示例：

> 用 lemo-animi 做一支 20 秒的黏土定格动画。
>
> 故事是一只小企鹅第一次做早餐，煎饼抛高了，落在自己头上。它愣了一下，最后自己笑了。
>
> 做成竖屏，要中文旁白和字幕，有配乐和动作音效，不要片头片尾。先给我看角色和主要背景，等我确认以后再继续。
>
> 其他制作细节你来决定。

这段话交代了故事、时长、风格、画面方向和声音要求。你也可以只讲故事，让它把没说清楚的选项一起问出来。

选风格时，不用记英文名字。想要软乎乎的小动物，可以试羊毛毡；想要活泼一点的日常小喜剧，可以试黏土；如果喜欢旧玩具的感觉，就看看铁皮和木偶。先打开[官方画廊](https://lemomo-ai.github.io/lemo-animi/zh/)看一圈样片，比读风格说明更容易选。

还有一点要有预期：**一句话开始，后面仍然需要制作时间。** 按项目给出的估算，40 秒短片需要生成约 20—26 张图，制作可能要一小时左右或更久，返工还会增加时间。第一次做短一点，也方便熟悉整个过程。

## 我比较看重的，是做完以后还能接着改

用 AI 做东西，经常会遇到这种情况：整体挺喜欢，但某个地方看着不对，又说不清该怎么改。

动画更容易碰到。角色落地太轻，某个表情一闪就过去，最后一句话还没说完，画面已经结束了。这些问题，看完整段之后再回聊天框描述，很容易漏。

lemo-animi 做了一个审片页面。片子出来以后，你可以边看边暂停，在有问题的那一刻写意见。

不用写什么专业术语，就说自己看到的问题：

> 这里太快了，我还没看清企鹅的表情，停一下再继续。

> 最后这句旁白说完以后，让画面多留一会儿。

页面会带上时间和镜头位置。提交以后，AI 按意见修改，再给出新版本。满意了再点“通过”。涉及补画角色或动作的修改，也可能需要重新生图。

我觉得这个设计挺实用。第一次就把脑子里的东西全部讲清楚，很难。很多时候，得先看到一个版本，才知道自己到底想要什么。

能把具体意见留在具体画面上，这件事就好沟通多了。

## 它为什么能做出来

看完它的制作方法，我觉得挺好理解。

先把角色、背景和不同动作画出来，再按故事需要安排它们什么时候出现、怎么移动、停多久，最后加上声音。

下面这张官方示意图就很直观：同一只企鹅，先有角色设定，再有拿锅、抛煎饼的不同姿势，配上厨房背景，最后组成影片画面。

这个 Skill 把不少做片子的经验也写进去了。角色要足够大，观众才看得清表情；动作要有准备和停顿，看起来才有分量；故事到最后，要把前面埋下的事情交代完。

它还会检查一些常见问题，比如角色换个镜头就变样、脚没踩住地面、字幕看不清。检查也有边界，旁白听着顺不顺、笑点能不能成立，还是得自己把片子完整看一遍。

对普通用户来说，这套方法省掉了不少自己摸索和来回切换工具的工夫。你需要花心思的地方，变成了想清楚故事，以及看完以后提出具体意见。
